# FC-16 视觉改造规范（封面 / 帮助页 / btnicon / 视差 / 扑克精灵）

目标：标题画面即封面（fc16mk `--cover 30` 取第 30 帧，标题必须从第 0 帧起就完整好看）、
界面按键提示一律走 `btnicon`、适合滚动的游戏加视差、扑克牌游戏复用 balatro 精灵表。

## 1. 开机 Splash = 封面，随后才是交互菜单（所有游戏）

**封面（--cover 30）取的是 Splash 段**，Splash 里禁止出现任何菜单/提示/统计文字。

- 帧循环：`state = "splash"`（初始）→ 第 90 帧（或 Ⓐ/Menu 按下）→ `state = "title"`（交互菜单，可保留
  模式/难度/最高分/开始提示/帮助入口——这些放菜单里是合理的，只是不能出现在 Splash 上）。
- Splash 画面 = **纯主视觉**：主题英雄画面（游戏自烘焙精灵的微距特写、角色/棋子/载具构图、场景剪影）
  + 大号游戏 logo。不放署名/版权行、不放副标题堆叠——封面只有画面和 logo。
- 英雄画面要有"封面感"：主体大（占画面 1/3 以上）、构图居中或三分位、色彩聚焦；不是把菜单背景
  原样搬来。装饰必须 `_init` 生成、frame 0 完整。
- 交互菜单（title 态）保持整洁即可，不再承担封面职责；Ⓨ 帮助入口放菜单里。

**必须有：**
- 大号游戏标题（`print` + `scale` 3–4，或程序化像素字/logo 装饰）。构图居中偏上或三分位，不要顶格。
- 与主题相关的装饰视觉：程序化生成（精灵烘焙已有素材、主题图形、色块构图均可）。
  必须在 `_init` 生成、不依赖运行帧数累积（frame 0 不能是空场）。
- 一行（最多两行）开始提示：`按 Ⓐ 开始` 风格，用 `btnicon("a")`；有菜单的游戏用菜单项代替。
- 最高分/版权行可保留一行小字，放底部，弱化颜色。

**禁止：**
- 操作说明列表 / 多行按键说明堆在标题上。
- 主提示闪烁（封面帧可能正好处于灭的相位）；装饰动画（星星、落块、浮云）可以动。
- 大面积空白无装饰。

**帮助二级页（操作复杂的游戏才需要）：**
- 标题画面加一项 `Ⓨ 操作说明`（`btnicon("y")`）；进入后整页列出操作表：
  每行 `btnicon(键) + 功能说明`，两列排版；`Ⓑ 返回`。
- 简单游戏（≤2 个操作）不加帮助页，标题一行提示即可。
- 游戏内 HUD 的按键提示同样走 btnicon；游戏进行中不必要的常驻提示删除或只在开局头几秒显示。

**判断"复杂"**：≥3 个不同操作，或有不易发现的机制（暂存/道具/切换/组合键）→ 帮助页。

## 2. btnicon 用法（所有游戏）

```lua
print("按 " .. btnicon("a") .. " 开始", 88, 200, 7)
```

- 可用名称（区分大小写）：`pad dpad up down left right a b x y lb lt rb rt view menu ls rs l3 r3 guide`
- 返回 UTF-8 图标字符串可直接拼接；未知名称返回 nil（只用上表内的名称）。
- 替换对象：文案里所有文本按键名——`Menu`→`btnicon("menu")`、`View`→`btnicon("view")`、
  `Ⓐ/A 键`→`btnicon("a")`、方向键→`btnicon("dpad")` 或四个 `left/right/up/down`。
- 注意：新主机没有 Select 键。旧文案 "Select" 一律改绑到实际使用的键（查代码确认 btnp 编号后映射）。
- 旧代码里的圈圈 Unicode（ⒶⒷⓍⓎ）也替换成 btnicon。

## 3. 视差滚动（flappy / thunder / mario）

- 至少两层背景，按滚动距离不同系数移动（远层 0.2–0.3、近层 0.4–0.6）。
- 平铺周期用 `% 周期` 处理无限滚动；装饰元素在 `_init` 固定生成（种子固定），frame 0 即有画面。
- 纯装饰，不参与碰撞与逻辑；绘制在玩法元素之前、背景色之后。
- 不适合的游戏不要硬加（无相机滚动的固定屏游戏不做）。

## 4. 扑克牌精灵表复用（doudizhu / holdem）

`tools/cards.bin`（64KiB）= demo balatro 精灵表前 256 瓦片：52 张牌面 + 6 张牌背。

- 构建加 `--sprites tools/cards.bin`（README 命令同步）。
- 布局公式（与 demo balatro 一致）：
  ```lua
  local function band_tile(base, idx) return base + flr(idx / 8) * 32 + (idx % 8) * 2 end
  local function card_tile(s, r) return band_tile(0, s * 13 + r) end  -- 32×32 牌面
  -- 牌背：band_tile(224, k)，k = 0..5
  ```
- 牌面绘制：`spr(card_tile(s, r), x, y, 2, 2)`（32×32 像素，含 1px 白边与圆角，自带红/黑花色与角标点数）。
- 花色/点数顺序（demo balatro 的 deck 图集）：s `0=♦ 1=♣ 2=♥ 3=♠`；r `0=A, 1=2 … 9=10, 10=J, 11=Q, 12=K`。
  各游戏自己的 suit 编码需写映射表对齐（注意 demo 的 0/1 与常规"红先黑后"习惯不同）。
- 游戏自烘焙的 UI 精灵全部挪到 ≥256 号瓦片（烘焙基址 +256），避免覆盖牌面区。
- 斗地主的大小王不在精灵表内（表里的 joker 是小丑角色卡）：保留原程序化绘制，可顺手美化。
- ⚠️ `spr(t,…)` 收瓦片号，`sspr(sx,sy,…)` 收**像素**。用瓦片号做 sspr 源时必须换算：
  `local function tile_px(t) return (t % 16) * 16, flr(t / 16) * 16 end`（参考 doudizhu.lua 的 tile_px 用法）。
- 牌桌布局按 32×32 牌面重新排版（手牌扇形/叠放间距），保持可读与点击/选择热区正确。

## 5. 构建与验证

- `tools/build_all.py`：封面统一 `--cover 30`，写出到 `carts/<游戏>.fc16.png`。
- 每个游戏：构建 → headless（无 Lua 错误）→ 截图标题画面人工目检（构图完整、提示用图标、无文字墙）。
